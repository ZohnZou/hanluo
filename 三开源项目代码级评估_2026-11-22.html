一句话结论：这三个仓库没有一个是「抄来就能用」的整包，但每个都有一块真正的金子。Detect 的金子 = 防前视测试 + 统计校验方法论（算法已被我吸收透）；AlphaMaster 的金子 = 因子表达式引擎 + 确定性版本治理（「RL」是噱头）；PA_Agent 的金子 = 程序确定性预判 + AI 校验纠偏的「三明治架构」（两阶段决策是包装）。

一、Detect_support_and_resistance_levels（DENSITY SR 支撑阻力检测）

定位 已深度吸收 V3 融合算法

基于 K 线自动检测支撑/阻力位，输出触及概率 × 守住概率。这个仓库我早在 srlab 模块就移植过（base.py/pivots.py/profile.py/labeling.py/metrics.py/probability.py/placebo.py 头注释都注明「移植自 DENSITY-SR」）。所以重点不是「要不要抄」，而是「V3 密度检测器还剩什么没抄、值不值得抄」。

代码级核心：V3 融合是「两层结构」，密度证据被赶出了排序

这是本次读码最重要的发现。V3 的融合分两层（detectors.py:581 V3Fusion.detect()）：

# 定位层 loc（决定"位放哪"）——密度证据在这里
loc_sup = 1.0*vp + 0.8*close + 1.6*pivot   # 成交量剖面+收盘堆积+枢轴聚集

# 排序层 edge（决定"谁排前面"）——密度证据权重全为 0
edge = 1.0*log1p(n_events) + 0.8*stale
# V3Params 明确把 w_hold_wilson / w_vp_edge / w_pivot_edge 全置 0

也就是说：密度检测器（成交量剖面+收盘堆积+枢轴聚集）在 V3 里只负责「生成候选位」，完全不参与最终排序。真正决定排序的只有 log1p(触及次数) + 0.8×陈旧度。这是它从 V2 失败里学到的最大教训——把「能不能赚」（edge）和「会不会停」（p_stall）拆开。

三个密度证据的具体实现

  • 成交量剖面 Volume Profile（profile.py:62 volume_profile()）：0.25 ATR 分箱 + 体积守恒（每根 K 线成交量均摊到覆盖箱，sum(vp)≈sum(volume)）+ 高斯平滑 + robust_z。这是对旧版「全额累加放大 15.8 倍」bug 的修复。
  • 收盘堆积 Close Clustering（profile.py:94 point_profile()）：收盘价按成交量加权、高斯核散布，代表「市场认可的价格」。
  • 枢轴聚集 Pivot Cluster（detectors.py:276 _pivot_profiles()）：来自因果 ZigZag（pivots.py:48，k_atr=2.0，带 confirm_idx 因果确认）的前低/前高，role reversal 角色互换。

硬证据：守住率模型里，密度特征是「负系数」

解析仓库自带的 data/prob_models.json（最硬的证据，不是看代码猜）：

系数touch 支撑hold 支撑hold 阻力含义
dist-1.80+0.335+0.75距离是主驱动
width+0.18+0.267+0.113区宽

结论铁证：守住率完全由 dist + width（距离+带宽）驱动，密度强度特征在守住模型里要么不显著、要么方向反了。这正是 placebo 也具备的信息。守住率「越远越守得住」是距离主效应，不是定位能力。

防前视机制：这个仓库的灵魂（最值得学）

  • 因果快照隔离（base.py:37 Ctx）：检测器只能读 [:t+1]，评测器只能读 t+1..t+horizon，walkforward.py:112 构造时物理截断数组。
  • 枢轴因果确认（pivots.py:28 confirm_idx）：ZigZag 一次算出全部枢轴，但每个记录 confirm_idx（反向走出 k*ATR 那一刻），view_at(t) 只放行已确认的。
  • 自动化防泄漏测试（leakage.py，7 个测试）：test_no_future_dependence（污染 t 之后数据、输出必须逐位不变）、test_pivot_causality、test_volume_conservation 等。这个「污染未来」的测试思路可以直接抄。

二、AlphaMaster（全自动量化因子挖掘）

定位 RL 名不副实 因子表达式引擎是金子

README 说的「深度神经网络强化学习」对不上代码。代码里没有 RL 环境、没有状态转移、没有价值函数/Critic，本质是「用 REINFORCE 训练一个 decoder-only Transformer，自回归生成逆波兰(RPN)公式 token 序列」——离散公式进化，不是强化学习。

代码级核心：REINFORCE 生成公式，不是 RL

  • 策略网络（alphagpt.py:219 AlphaGPT）：3 层 LoopedTransformer、d_model=96。注意 MTPHead 已被作者自己简化成单 head（返回 (logits, None)），head_critic 已删（value 恒 None）——纯 REINFORCE，无 actor-critic。
  • 动作空间 = 词表 token：127 个 token（65 特征 + 62 算子），每步采一个 token 拼 RPN，MAX_FORMULA_LEN=8。没有环境状态转移，「状态」就是当前前缀 token + 栈深度。
  • ConstrainedSampler（engine.py:145）保证 100% 合法公式：用「栈深度 delta」约束（特征 +1、算子 1-arity），mask 掉会栈下溢或最终栈深≠1 的 token，非法 logit 打到 -1e9。这是这套代码最精巧的部分。
  • Reward：_eval_formula_task → vm.execute() 算因子 → bt.evaluate_fold() 回测打分，episode 级一次性给，REINFORCE 广播给公式内每个 token。
  • 抗搜索坍塌堆料：Elite Replay 池（Top-60 温度采样）、因子池相关性惩罚（|corr|>0.85 则 reward×0.8）、熵坍塌检测 + 重启（55 次 MAX_RESTARTS）。

StackVM + 算子集：写得最好、最值得抄的模块

62 个算子（ops.py：44 初始 + 3 横截面 + 8 Task3.3 + 7 Task3.4）：基础算术（ADD/SUB/MUL/DIV/GATE/JUMP/DECAY）、时序（TS_MEAN/STD/RANK/QUANTILE/ZSCORE/WINSORIZE，窗口 5/10/20）、动量（MOMENTUM/DELTA/TS_ARG_MAX）、横截面（CS_RANK/CS_SCALE/CS_NEUTRALIZE）、归一化（CLIP/SIGMOID/TANH_SQUASH/IF_GT）。

StackVM.execute()（vm.py:221）是标准 RPN 栈机解释器：特征 token push 张量 → 算子 token pop 操作数 → 计算 → push。栈最后必须剩 1 个元素。这是「因子公式即数据」的通用执行引擎，市场无关、数据无关，可直接移植到 A 股因子库。

算子因果性极严谨：所有时序算子零填充 + unfold 滑窗（只用 [t-w+1, t]），无 look-ahead。_normalize_output() 输出标准化分两级：N>1 跨品种截面 zscore，N=1 滚动时序 zscore（窗口 500，严格因果），clip [-3,3]。

版本治理 + 防过拟合（对寒洛最有借鉴价值的两块）

① 确定性版本治理（比 factor_ledger 台账强）

VOCAB_VERSION = "v" + sha256("\n".join(token_names))[:12]   # vocab.py:48

词表组成/顺序一变，版本号必变。FormulaVocab.verify() 加载 checkpoint/策略时校验版本，不匹配抛 VocabVersionMismatchError 拒绝加载。这是「公式可执行性 + 版本一致性」的硬校验，不是人工台账。寒洛的 factor_ledger.json 可以升级成这个。

② 防过拟合（齐全）

  • Walk-Forward（engine.py:95 _build_walk_forward_folds）：rolling 5 折 + gap=20，注释讲清了「expanding window 会让早期折 val 被后续折 train 包含」的坑。
  • OOS Sortino 门控：val 分数乘 0.1~1.2 系数，OOS Sortino≤0 重罚。
  • 相关性/重复/稀疏惩罚：|corr|>0.85 reward×0.8、连续同 token 罚 0.3、暴露度<0.05 跳过。
  • estimate_periods_per_year（backtest.py:33）：按数据时间戳自动估年化 bar 数，不写死。这是移植 A 股最关键一处——A 股日线 ~244 bar/年，不修正年化会放大 26 倍。

三端信号一致性：position = tanh(factor)，但有两处真实口径漂移

训练/回测端 compute_target_positions_stateless、实盘端 runner.py _compute_targets、live_signal.py evaluate_signal 三端共享同一 StackVM + 同一 compute_features()，因子数值本身一致。但存在两处漂移值得警惕：

  • 多公式合并口径：训练/回测是「单公式→tanh」，实盘 runner 是「多公式→各自 tanh→平均」——信号平均 ≠ 仓位平均。
  • 阈值语义：训练端 |pos|<0.05 置零（连续仓位），实盘端 |pos|>=thr 判方向（±1/0 三档），边缘区行为不同。

工程评价：好 — registry.py（声明式注册+原子校验）、vocab.py（sha256 版本化）、ConstrainedSampler、原子写入（tmp+os.replace）、PARALLEL_EVAL 试过才关（8 workers 反而慢 55%）。遗留 — ops.py:134 _ema 是死代码占位符（返回 0）、QKNorm 死代码、MTPHead 空壳、注释漂移（写「66 算子」实际 62、写「20 features」实际 65）。

AlphaMaster 结论：别抄「RL 搜公式」的皮，抄「因子表达式引擎 + 版本治理 + 防过拟合」的骨。它的核心竞争力不是 RL，而是 RPN 因子表达式引擎 + 确定性版本治理 + walk-forward 防过拟合——这三样对寒洛 A 股体系是可直接移植的增量。RL 搜公式本身：搜索空间 8.7×10^16，被逼到 TRAIN_STEPS=9000/重启 55 次，纯 CPU 比 GPU 快 2.3 倍，是「大海捞针+疯狂堆算力」形态，且 IC 口径是单标的时序 IC、不是 A股横截面 IC，直接搬会水土不服。寒洛现有「人肉提炼 + 网格扫描」在可解释、可控制、样本量需求低上反而占优。

三、PA_Agent（价格行为 AI 智能体，Al Brooks 风格）

定位 三明治架构是金子 两阶段是包装

README 说的「两阶段 AI 分析」（市场诊断→交易决策）是包装，代码里真正的核心是「AI 产出 + 程序确定性裁判（DecisionNodeEngine）双向合并」的三明治架构——AI 输出通过校验后，程序会 in-place 修改 JSON，把程序算出的节点合并进 trace，AI 只能通过 node_overrides 覆盖（受 LOCKED_NODES/OVERRIDABLE_NODES 权限控制）。

代码级核心：两阶段编排（two_stage.py，1340 行，Step 0-24）

Step 0  check_preflight_data(frame)  → AI 调用前的确定性数据闸门
Step 1  build_stage1  → 阶段一诊断 JSON
Step 2  validate_with_retry  → 校验 + 反馈重试
Step 3  route_strategy_files  → 策略文件路由
Step 4  read_for_stage2  → 经验库检索
Step 5  gate_result ∈ (wait,unknown) → 短路，不调模型，直接合成"不下单"
Step 6  build_stage2  → 阶段二决策 JSON → apply_stage2 程序补节点
Step 7  save_full  → 持久化
  • 阶段一（诊断）输入：KlineFrame（不可变快照 + EMA20/ATR14 + 程序预计算几何特征）。输出：cycle_position/direction/gate_result/gate_trace/node_overrides。
  • 阶段二（决策）输入：frame + 压缩版阶段一 JSON（_compact_stage1_for_stage2 只留 20 字段）+ 策略文件 + 经验库文本 + 决策姿态。输出：order_type/entry_price/take_profit/stop_loss。
  • 关键：check_preflight_data（bar≥20、EMA20/ATR14 非 NaN）不通过直接返回 insufficient_data，不花一次 API 调用。

程序确定性预判层（最值得抄的部分）

decision_nodes.py 把可量化判断交给确定性代码，AI 只做语义补全。核心是 judge_direction 的五信号投票：

  • EMA 斜率（±ATR 死区）
  • 加权收盘重心
  • HH/HL 结构
  • 趋势棒占优（1.5×）
  • 重叠度（0.45/0.65 阈值）

±3 阈值判定方向，中窗口冲突扣分。加上 judge_always_in（Always In 判定）、judge_momentum_strength（惯性强度）、judge_market_chaos（§1.3 extreme_tr，保守默认答「否」）。寒洛的 price_action_engine.py 有逐K演绎/缠论/支撑阻力，但没有「程序先给方向/惯性/Always In 确定性预判，AI 只做覆盖」这个模式。

一致性校验 + 硬约束代码化（AI 可靠性护栏）

思路是「程序确定性计算 = ground truth，AI 输出与它交叉校验 + 自动纠偏」，不是「第二段 AI 复查第一段 AI」。coherence_checks.py 主要检查：

  • 强制节点存在（gate_trace 必须含 1.1/1.2/1.3/2.1-2.5 节点）
  • bar_range 合法性、引用 K 序号必须在 frame 内、≥4 节点共用同一 bar_range 判模型偷懒
  • 交叉字段一致（node 1.2 的 branch 必须等于 cycle_position、node 2.3 必须等于 direction）
  • auto_fix_bar_by_bar_types()：bar_type 与程序相反时自动改回程序值

阶段二侧（json_validator.py）：_check_no_order_invariant（order_type=不下单时 entry/stop/target 必须全 null）、_check_trade_metrics（RR≥1.0、交易者方程：胜率×回报 > 败率×风险）、_check_breakout_order_basis。这些代码级最后闸门可以直接套到寒洛的 build_signal 交易提醒上。

市场周期分类 + 下单路由（面向外盘，A股要重写）

市场周期（cycle_enums.py）：spike / micro_channel / tight_channel / normal_channel / broad_channel / trending_tr / trading_range / extreme_tr——Al Brooks 周期位置。

下单路由（decision_nodes.route_order_method）按 cycle_position 映射：spike→市价单、micro/tight/normal_channel→突破单、broad_channel→限价单、trading_range→限价单、extreme_tr→不下单。这套面向外盘 MT5/期货（pending order、tick 最小跳动、ATR 结构止损），A股 T+1/涨跌停/无市价单语境大部分不适用，映射表必须重写。

经验库（半成品）+ AI 调用层

  • 经验库（experience_reader.py）：目录文件 + 三字段粗匹配（cycle_position + direction + patterns），无 embedding/向量检索、无自动写入闭环（纯读取，用户手工整理目录）。本质是「目录树 + 关键词打分」，价值有限。
  • AI 调用层（deepseek_client.py 986 行 + ark_gateway.py）：多网关适配矩阵（thinking 参数按网关分派）、KV prefix cache（复用 DeepSeek 硬盘缓存降费）、JSON 校验 5 类错误 + 多级修复链、回退链深（14 模型池 + 免费通道）。对单 DeepSeek 场景是明显负担。

PA_Agent 结论：最值得抄的是藏在深处的「程序确定性节点引擎 + 一致性校验」这套 AI 可靠性护栏，不是两阶段对话或经验库。它把 Al Brooks 判读体系拆成「算得动的用代码、算不动的用 AI、AI 输出再被代码纠偏」——这是 AI 决策可靠性的关键设计。落地优先级：先做「程序方向/惯性确定性预判喂给 DeepSeek」，再做「诊断→决策两阶段 + 代码级校验闸门」，最后才考虑决策树 markdown 化和经验库。

落地优先级（我的独立建议）

P0 · 值得马上做（AI 可靠性护栏）

  • 程序确定性方向预判喂给 DeepSeek：把 PA_Agent 的五信号投票（judge_direction + judge_always_in + judge_momentum_strength）落成寒洛的「方向预判层」，作为每日 DeepSeek 分析的锚定输入。寒洛现在 DeepSeek 是「一次性裸分析」，缺这个确定性锚点。
  • 一致性校验 + 硬约束代码化：build_signal 交易提醒套「下单必须三价齐全/不下单则价格全空/方向与诊断一致」的代码级最后闸门，不信任 prompt。

P1 · 值得规划（因子治理升级）

  • StackVM 因子表达式引擎：把 factors/（signal/sr_probability/direction/chanlun）封装成 token 化算子，让「因子公式 = 可执行 + 可版本化 + 可解码」。
  • 确定性版本治理：factor_ledger.json 升级为 sha256 硬校验（vocab.py 思路），防算子/特征顺序变更致历史因子失效。
  • walk-forward folds + estimate_periods_per_year：强化 full_param_scan 的切分 + 修正 A股日线年化口径。

P2 · 别做 / 低优先

  • V3 密度检测器移植：守住率增量≈0，竞品自己用系数证明了「密度=价格会停，不是进场能赚」。
  • RL 搜公式：大海捞针堆算力，A股短历史+横截面 alpha 性价比极低。
  • 经验库（目录+三字段）+ 下单路由（外盘）：价值低或水土不服。
